- [x] 2.2 实现当前会话历史加载，分别表达加载、错误和空状态，并将仓储消息稳定映射为 UI 消息。

- [x] 2.5 实现当前及非当前会话的确认删除，包括删除当前会话后选择第一条剩余会话，或删除最后会话后创建新的空会话。

## 3. 多轮发送和故障恢复

- [x] 3.1 将发送流程改为使用当前 `sessionId`，为每个新逻辑轮次生成一个客户端消息 ID，并且只追加一组乐观用户消息和助手加载项。
- [x] 3.2 发送成功后使用服务端返回的持久化消息对替换乐观消息，并保持当前会话不变。
- [x] 3.3 阻止重复发送点击，并在仓储发送请求进行期间禁止新建、切换和删除会话。
- [x] 3.4 发送错误后重新加载历史进行对账：将服务端实际完成的消息对恢复为成功状态，将末尾已持久化用户消息恢复为单个可重试的回复缺失轮次。
- [x] 3.5 使用原始会话 ID、规范化内容和客户端消息 ID 实现重试，不再追加用户气泡；存在未解决失败轮次时禁止发送新逻辑轮次。
- [x] 3.6 消息成功后刷新服务端排序的会话列表，成功时应用新标题和顺序，并确保元数据刷新失败不会影响已成功的消息。
